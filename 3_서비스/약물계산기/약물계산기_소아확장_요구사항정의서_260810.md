### 1.3 가장 큰 공백 — 소아 지속주입

성인은 `💉 성인계산기`·`💧 지속주입`·`🧮 직접계산` 3중으로 지원되는데,
**소아는 mcg/kg/min → ml/hr 로 가는 경로가 앱 안에 없다.** 소아 승압·진정 지속주입은
① 농도가 성인과 다르고 ② 체중 곱이 들어가 암산 오류가 잦은, **가장 위험한 구간**이다. → 2.4절

## 2. 요구사항 ① — 소아 내용 확장

### 2.1 정보구조 개편

```
👶 소아계산기
 ├─ [환자 바] 체중 입력 ⇄ 연령 선택 ⇄ Broselow 색상   ← 2.2
 ├─ 🚨 응급   : (기존 7카드) + 서맥 + 빈맥
 ├─ 💊 약물   : (기존 4카드) + 전해질·대사 + 항생제(선택)
 ├─ 💉 지속주입 ← **신규 서브탭**                      ← 2.4
 └─ 💧 수액   : (기존 3카드) + **수액 상한(MAX) 패널**  ← 3장
```

- 서브탭 3 → **4개**. 기존 서브탭의 카드 순서·내용은 **회귀 없이 유지**한다.
- 서브탭 추가에 따라 `showSub()`(995행)의 패널 배열에 `sub-civ` 를 추가한다.

### 2.2 환자 바 — 체중·연령·Broselow

| 입력 | 명세 | 상태 |
|------|------|------|
| 체중 (kg) | 현행 유지. 범위 **1~80kg** (필요 시 확대는 ⬜ 컨펌) | ✅ |
| 연령 선택 | 개월/세 선택 → **추정 체중 자동 입력** | ⬜ 매핑표는 컨펌 대기 (📄 설계서 `환자기본정보` 19행 참고값 존재) |
| Broselow 색상 | 체중 → 색상 배지 표시 (Gray/Pink/Red/Purple/Yellow/White/Blue/Orange/Green) | ⬜ 원내 Broselow 테이프 보유 여부·색상 구간 컨펌 필요 |

> **★ 안전 원칙 (앱 상단 고정 문구):**
> `연령 기반 추정 체중은 참고값입니다. 가능하면 실제 측정 체중을 사용하십시오.`
> 추정 체중으로 계산 중일 때는 결과 카드에 `추정체중 기준` 배지를 **상시** 노출한다.

### 2.3 신규 카드 — 서맥 · 빈맥

두 카드 모두 **체중 대입 계산 + 최대 용량 캡**을 함께 표시한다. 값은 전부 ⬜ 컨펌 대기.

**🐢 서맥 카드 (신규)**

| 항목 | 표시 형태 | 값 |
|------|-----------|-----|
| 1차 조치 (HR<60 + 관류 저하) | 문구 카드 | ⬜ (📄 설계서: CPR 우선) |
| Atropine | `⬜ mg/kg × 체중 = ○ mg` + 최소/최대 캡 | ⬜ (📄 0.02mg/kg · 최소 0.1 / 최대 0.5 / 총 3mg) |
| Epinephrine CIV | mcg/kg/min → **ml/hr 연동** (2.4) | ⬜ (📄 0.1~1 mcg/kg/min) |
| Dopamine CIV | mcg/kg/min → **ml/hr 연동** | ⬜ (📄 2~20 mcg/kg/min) |
| 경피 페이싱 | 문구 (용량 없음) | ⬜ 원내 장비·적응증 확인 |

**🐇 빈맥 카드 (신규)**

| 항목 | 표시 형태 | 값 |
|------|-----------|-----|
| Adenosine 1차 | `⬜ mg/kg × 체중` + 최대 캡 + **N/S flush량** | ⬜ (📄 0.1mg/kg · max 6mg · N/S 5ml flush) |
| Adenosine 2차 | 동일 | ⬜ (📄 0.2mg/kg · max 12mg) |
| 동기화 심율동전환 | `⬜ J/kg × 체중 = ○ J` (1차/추가) | ⬜ (📄 0.5~1 J/kg → 최대 2 J/kg) |
| Amiodarone (안정 VT) | mg/kg + 최대 캡 + **투여 시간** | ⬜ (📄 5mg/kg · max 300mg · 20~60분) |
| Lidocaine (대안) | mg/kg + 최대 캡 | ⬜ (📄 1mg/kg · max 100mg) |
| Amiodarone CIV | mcg/kg/min → ml/hr 연동 | ⬜ (📄 5~15 mcg/kg/min) |

- **정맥 부위 주의**(Adenosine: 상완 이상), **flush 필수** 문구를 카드에 고정 노출한다.
- 제세동(비동기)과 **동기화 심율동전환**은 에너지 체계가 다르므로 **카드를 물리적으로 분리**하고,
  동기화 카드에는 `SYNC 켜기` 체크 문구를 시각적으로 강조한다. (혼동 사고 방지)

### 2.4 신규 서브탭 — 💉 소아 지속주입 (CIV)

**가장 우선순위 높은 신규 기능.**

#### 2.4.1 동작

```
[선택] 약물 (Epi / Norepi / Dopamine / Dobutamine / Midazolam / Amiodarone / ⬜추가)
   ↓
[표시] 원내 표준 믹스 (예: "○ mg + ○ ml = 총 ○ ml, 농도 ○ mcg/ml")   ← 값 전부 ⬜ 컨펌
   ↓
[입력] 목표 용량 (mcg/kg/min)  ←→  [역산] 현재 ml/hr
   ↓
[출력] 주입속도 ml/hr (대형 판독창) + 용량 범위 슬라이더/스테퍼 + 자동 속도표
```

#### 2.4.2 계산식 — **기존 엔진 재사용 (신규 계산 로직 금지)**

V4의 `calcInfusion()` / `calcDoseFromRate()` (1998~2007행)와 `UNIT_DEFS` 를 그대로 쓴다.

```
ml/hr = dose(mcg/kg/min) × 체중(kg) × 60 ÷ 농도(mcg/ml)
```

- 소아 전용 계산 함수를 새로 만들지 않는다. **검증된 엔진 하나만 유지**한다(계산 이원화 = 사고 원인).
- 🧮 직접계산 탭에서 「소아 믹스 불러오기」로 프리필 가능하게 연결한다.

#### 2.4.3 소아 전용 안전 규칙

| 규칙 | 동작 |
|------|------|
| **소수점 방어** | 결과가 `< 0.1 ml/hr` 이면 `⚠️ 시린지 펌프 최소 유량 확인` 경고 |
| **10배 오류 방어** | 계산 결과가 해당 약물 표준 범위(⬜ 컨펌)의 **10배 이상/이하**면 붉은 경고 배너 |
| **총 수액량 연동** | CIV 주입량(ml/hr)을 **3장 유지수액 상한 계산에 합산** (소아는 약물 희석액도 수액이다) |
| **농도 이원화 금지** | 한 약물에 원내 표준 농도 **1개만** 노출. 성인 농도와 다르면 `소아 전용 농도` 배지 |
| **고농축 경고** | 말초 라인 사용 시 주의가 필요한 약물은 `중심정맥 권장` 배지 (⬜ 대상 약물 컨펌) |

#### 2.4.4 데이터 스키마 (값은 비워 둔 채 구조만 확정)

```js
// 소아 지속주입 — 값의 정본은 「병원 컨펌 파일」. null = 미확정(앱에서 "— 확인 필요" 표시)
const PEDS_CIV = [
  { id:'epi',   name:'Epinephrine',  kr:'에피네프린',
    mixText:  null,   // 예: "○mg + ○ml = 총 ○ml"        ⬜
    concMcgMl:null,   // 농도 (mcg/ml)                     ⬜
    doseMin:  null,   // mcg/kg/min 하한                   ⬜
    doseMax:  null,   // mcg/kg/min 상한                   ⬜
    step:     null,   // 티트레이션 스텝                    ⬜
    line:     null,   // 'central' | 'peripheral' | null    ⬜
    caution:  null,   // 주의 문구                          ⬜
    src:      null }, // 근거 파일·페이지                   ⬜
  // norepi / dopamine / dobutamine / midazolam / amiodarone / … (컨펌 파일 목록에 맞춰 확정)
];
```

> **렌더 규칙:** `concMcgMl === null` 인 약물은 **계산을 수행하지 않고** 카드에
> `⬜ 원내 표준 농도 미확정 — 병원 확인 필요` 만 표시한다. 임시 농도로 계산하지 않는다.

| 기도 장비 | uncuffed ETT · i-gel 크기 열 추가 | ⬜ (📄 설계서에 값 있음) |
| 정상 활력징후 | 체온 범위 · SpO2 하한을 연령군별로 | ⬜ (📄 설계서에 값 있음) |
| 인공호흡기 | 환기 RR을 활력징후 RR과 **분리** | ⬜ (📄 설계서에 별도 값 있음) |
| 항구토제 | 연령 제한 배지 (예: `≥6개월`) | ⬜ 원내 방침 확인 |
| 경련 | 투여경로별(IN/IM/IV) 용량 분리 표기 | ⬜ (📄 설계서에 값 있음) |
| 아나필락시스 | Epinephrine CIV 행 추가 → 2.4 연동 | ⬜ |
| 전해질·대사 (신규) | 저혈당·고칼륨혈증·저칼슘 등 소아 교정 | ⬜ **컨펌 파일에 있으면 추가, 없으면 만들지 않음** |

## 3. 요구사항 ② — 수액 최대 상한(MAX)

> 오너 요구: **"수액도 최대 맥스 얼마까지 줄지"**
> 현재 앱은 *1회 얼마*만 답한다. 실무에서 위험한 질문은 **"이제 그만 줘야 하나?"** 다.

### 3.1 상한은 한 종류가 아니다 — 4종으로 분리 정의

| # | 상한 종류 | 답하는 질문 | 단위 |
|---|-----------|-------------|------|
| **M1** | **1회 볼루스 상한** | "이번 한 번에 최대 몇 ml?" | mL/kg, 절대 mL 캡 |
| **M2** | **누적 볼루스 상한** | "지금까지 총 ○ml 줬는데, 얼마나 더 되나?" | 총 mL/kg, 총 절대 mL |
| **M3** | **유지수액 상한** | "유지수액을 시간당 최대 몇 ml까지?" | mL/hr 캡 |
| **M4** | **최대 주입 속도** | "이 볼루스를 몇 분에 걸쳐 주나 / 얼마나 빨리 가능한가?" | mL/kg/hr, 투여 소요시간 |

**M2가 이번 요구의 핵심**이다. M1만 있는 지금 구조로는 반복 투여 시 총량을 알 수 없다.

### 3.2 M1 — 1회 볼루스 상한

```
1회 볼루스량 = 체중(kg) × 상황별 mL/kg
              ↓
        min( 위 값 , 절대 상한 mL )   ← ⬜ 컨펌 대기
```

- **절대 상한(체중 큰 소아 방어)**: 예컨대 체중 60kg 소아에 20mL/kg = 1,200mL 가 계산된다.
  성인 1회 볼루스 관행을 넘어서므로 **절대 mL 캡이 필요**하다. 캡 값 ⬜ **컨펌 대기**.
- 캡이 걸리면 결과 옆에 `⚠️ 상한 적용됨 (계산값 1,200ml → ○ml)` 를 **반드시 병기**한다.
  (V4의 Actilyse 90mg 상한 처리 방식과 동일한 UX를 승계)

### 3.3 M2 — 누적 볼루스 상한 + 트래커 (신규 UI)

#### 3.3.1 화면

```
┌─ 💧 수액 누적 (체중 15kg · 저혈량성 쇼크) ─────────────┐
│  누적 투여      300 ml   ( 20 mL/kg )                 │
│  ████████████░░░░░░░░░░░░░░░░  33%                    │
│  상한 ⬜ 확인 필요   ·   남은 여유 ⬜                    │
│                                                        │
│  [ + 1회 볼루스 300ml 추가 ]   [ 직접 입력 ]  [ 초기화 ] │
│                                                        │
│  기록: 1차 300ml (14:02) · 2차 300ml (14:15)           │
└────────────────────────────────────────────────────────┘
```

#### 3.3.2 동작 규칙

| 규칙 | 내용 |
|------|------|
| 카운터 | `+ 볼루스 추가` 버튼 또는 직접 입력으로 누적. **투여 기록은 화면 세션 한정** (저장·전송 없음) |
| 표시 단위 | 항상 **`○ ml (○ mL/kg)` 양쪽 병기** — 단위 혼동 사고 방지 |
| 진행 바 | 누적 ÷ 상한. **상한이 ⬜ 미확정이면 바를 그리지 않고** `상한 확인 필요` 문구만 |
| 초기화 | 체중 변경·쇼크 유형 변경 시 **자동 초기화 + 안내 토스트** |
| 재평가 알림 | 볼루스 1회 추가할 때마다 `⚠️ 재평가: 호흡음·간비대·의식·소변량` 체크 문구 노출 |
| 기록 성격 | 화면 계산 보조일 뿐 **간호기록이 아님**을 카드 하단에 명시 |

#### 3.3.3 경고 등급

| 누적 수준 | 표시 |
|-----------|------|
| 상한의 50% 미만 | 평상 (파랑) |
| 50% 이상 | `⚠️ 재평가 권고` (주황) |
| 상한 도달·초과 | `🚨 상한 도달 — 승압제·의국 상의` (적색 배너, 계산은 계속하되 강조) |
| 심인성 쇼크 유형 선택 시 | 임계값과 무관하게 **상시 적색 주의 배너** (수액 과부하 위험) |

> 앱은 **투여를 막지 않는다.** 판단은 의료진의 몫이며, 앱은 "지금 총량이 얼마인가"를 정확히 보여줄 뿐이다.

### 3.4 M3 — 유지수액 상한

현재 `maintenance()` 는 Holliday-Segar 를 그대로 쓰므로 **체중이 커질수록 무한히 증가**한다.

```
현재: 40kg → 80 ml/hr · 60kg → 100 ml/hr · 80kg → 120 ml/hr  (캡 없음)
```

| 요구 | 명세 |
|------|------|
| 상한값 | ⬜ **컨펌 대기** — 원내 소아 유지수액 최대 mL/hr |
| 적용 체중 | ⬜ 컨펌 (몇 kg부터 성인 기준으로 넘어가는지) |
| 표시 | 캡 적용 시 `계산값 120 ml/hr → 상한 ○ ml/hr 적용` 병기 |
| **총 수액 부하 합산** | 유지수액 + **CIV 주입량(2.4)** + 항생제 등 간헐 주입을 합산한 `총 ml/hr` 카드 신설 |
| 제한 전략 | 📄 설계서 주석 "수술 후/중환자는 제한적 수액 전략" → ⬜ 원내 방침 확인 후 문구 반영 |

> **총 수액 부하 합산 카드**는 이번 요구("최대 얼마까지")에 대한 실질적 답이다.
> 소아는 승압제 희석액만으로도 유지수액을 넘길 수 있다.

### 3.5 M4 — 최대 주입 속도 / 소요 시간

| 항목 | 명세 | 상태 |
|------|------|------|
| 볼루스 투여 시간 | 상황별 권장 소요시간(분) 표시 | ⬜ (📄 설계서: 5~20분 등) |
| 환산 속도 | `볼루스량 ÷ 시간 = ○ ml/hr` 을 함께 표시 (펌프 설정용) | 계산은 확정 |
| 펌프 상한 | 기기 최대 유량 초과 시 `⚠️ 압력백/신속주입 필요` | ⬜ 원내 장비 확인 |

### 3.6 데이터 스키마 — `FLUID_MAX`

```js
// 수액 상한 — 값의 정본은 「병원 컨펌 파일」. null = 미확정 → 앱은 "— 확인 필요" 표시
const FLUID_MAX = [
  { id:'hypovolemic', label:'저혈량성 쇼크 / 탈수',
    bolusMlKg:   null,  // M1 1회 mL/kg                    ⬜
    bolusCapMl:  null,  // M1 1회 절대 상한 mL             ⬜
    cumMlKg:     null,  // M2 누적 상한 mL/kg              ⬜ (📄 참고: 60)
    cumCapMl:    null,  // M2 누적 절대 상한 mL            ⬜
    minutes:     null,  // M4 권장 투여 소요시간(분)        ⬜
    fluidType:   null,  // 'N/S' | '균형수액' | …           ⬜
    warn:        null,  // 유형별 상시 경고 문구            ⬜
    src:         null },// 근거 (컨펌 파일 시트·행)         ⬜
  // septic / cardiogenic / anaphylaxis / trauma / dka / neonate / hypernatremia / …
];

const MAINT_MAX = {
  capMlHr:      null,   // M3 유지수액 최대 ml/hr          ⬜
  adultFromKg:  null,   // M3 성인 기준 전환 체중          ⬜
  note:         null };
```

**렌더 규칙 (필수):**
1. `null` 인 필드는 **절대 기본값으로 대체하지 않는다.** `— (병원 확인 필요)` 로 그린다.
2. `cumMlKg` 가 `null` 이면 누적 트래커의 **진행 바·남은 여유·경고 등급을 모두 비활성**하고, 누적 합계만 표시한다.
3. 카드 상단에 `⬜ 병원 컨펌 대기` 배지를 노출한다. (V4의 `★ 약제부 검증 중` 배지 스타일 승계)

### 3.7 성인 수액 상한 (범위 밖 — 판단 필요)

오너 요구가 소아 맥락에서 나왔으므로 **1차 구현은 소아 한정**으로 잡았다.
성인 수액 상한(패혈증 초기 30mL/kg 등)도 같은 엔진으로 확장 가능하나,
**별도 컨펌이 필요한 다른 데이터**이므로 이번 범위에 포함하지 않는다. → 11장 결정 대기

## 4. 병원 컨펌 파일 연계 규격 ★

> 오너가 제공할 **「병원 컨펌 파일」이 모든 임상 수치의 정본**이다.
> 아래는 그 파일이 도착했을 때 **손대지 않고 그대로 앱에 들어가게 하는** 절차다.

### 4.1 접수 규칙

| 항목 | 규칙 |
|------|------|
| 저장 위치 | `3_서비스/약물계산기/refs/병원컨펌_소아_<YYMMDD>/` (새 폴더) |
| 원본 취급 | **불변.** 받은 파일은 이름만 정리하고 **내용 수정·보정 금지** |
| 출처 README | 폴더에 `README_<YYMMDD>.md` — 누가·언제·어떤 회의/부서에서 컨펌했는지 기록 (TPA 사진 폴더 선례 따름) |
| 사진(HEIC)일 때 | 원본 유지 + 판독 결과를 별도 `.md` 로 옮겨 적고, **판독 불확실 구간은 `⬜ 판독 불가` 로 남긴다** |

### 4.2 포맷별 처리

| 포맷 | 처리 |
|------|------|
| `.xlsx` | 시트·열을 4.3 매핑표에 대응. **가능하면 이 형식 권장** (재컨펌·갱신이 쉬움) |
| `.docx` / `.pptx` / `.pdf` | 본문에서 값을 추출해 `refs/병원컨펌_소아_<YYMMDD>/추출값_<YYMMDD>.md` 로 정리 후 매핑 |
| 사진 | 위와 동일. 판독자·판독일 명기 |

### 4.3 매핑표 — 컨펌 파일 → 앱 상수

| 컨펌 파일 내용 | 앱 반영 위치 | 비고 |
|---------------|-------------|------|
| 연령↔체중, Broselow 색상 | `PEDS_WEIGHT` (신규) | 2.2 |
| 정상 활력징후 | `VITAL_TABLE` (971행) | 기존 값 **덮어쓰기 여부는 대조 후 결정** |
| 기도 장비 | `AIRWAY_TABLE` (958행) | uncuffed·i-gel 열 추가 |
| 서맥 / 빈맥 | `PEDS_BRADY` · `PEDS_TACHY` (신규) | 2.3 |
| 심정지 / 경련 / 아나필락시스 / RSI / 진통·진정·항구토 | `updatePeds()` 내 하드코딩 → `PEDS_DOSE` (신규 배열) 로 이관 | 5장 |
| **소아 지속주입 농도·용량범위** | `PEDS_CIV` (신규) | 2.4.4 |
| **수액 볼루스·누적 상한·유지 상한** | `FLUID_MAX` · `MAINT_MAX` (신규) | 3.6 |
| 제세동 / 심율동전환 에너지 | `PEDS_ENERGY` (신규) | 계산식 유지 여부 확인 |

### 4.4 대조·충돌 처리 (필수 절차)

컨펌 파일 값과 **현재 앱 값이 다를 때**의 처리:

```
1) 컨펌 파일 값을 채택한다.               (컨펌 파일이 정본)
2) 차이를 전부 `refs/_소아컨펌_차이표_<YYMMDD>.md` 에 기록한다.
   ┌ 항목 │ 현재 앱 값 │ 컨펌 파일 값 │ 처리 ┐
3) 차이표를 오너(칩스)에게 보고한 뒤 반영한다. 조용히 바꾸지 않는다.
4) 컨펌 파일에 **없는 항목**은:
   - 이미 앱에 있으면 → 값을 그대로 두고 `⬜ 미컨펌` 배지를 단다.
   - 앱에 없으면      → **만들지 않는다.**
```

> `build_nfh.py` 의 마스터 대조 → `_마스터미일치.txt` 패턴을 그대로 따른다. **경고만 하고, 값은 임의 수정하지 않는다.**

### 4.5 데이터 무결성 원칙 (CLAUDE.md 0장 재확인)

1. 컨펌 파일에 없는 임상 수치는 **추정·교과서값으로 채우지 않는다.**
2. 값이 없으면 **비워 두고 `— 확인 필요`** 로 노출한다.
3. 설계서(`PALS_…설계서.xlsx`) 값은 **참고 표시**로만 쓰고, 앱 계산에는 **넣지 않는다** (컨펌 전).
4. 막히면 진행하지 말고 **오너에게 묻는다.**

## 5. 데이터 구조 개선 — 하드코딩 이관

현재 소아 데이터는 `updatePeds()` 안의 HTML 문자열에 박혀 있어, 컨펌 파일이 바뀔 때마다
**템플릿을 손대야 하고 → 오타·누락 위험**이 크다.

| 단계 | 내용 |
|------|------|
| 5.1 | 소아 용량 데이터를 **상수 배열로 분리** (`PEDS_DOSE`, `PEDS_CIV`, `FLUID_MAX`, …) |
| 5.2 | `updatePeds()` 는 **배열을 렌더만** 한다 (값 하드코딩 금지) |
| 5.3 | 모든 항목에 `src` 필드(근거 출처) 필수 — 출처 없는 값은 넣지 않는다 |
| 5.4 (선택) | 컨펌 파일이 엑셀이면 `data/소아_원본_<YYMMDD>.xlsx → build_peds.py → 인라인 삽입` 파이프라인 구축 → 11장 결정 대기 |

> 5.4는 간호기록 앱의 엑셀→빌드 방식(CLAUDE.md 3장)과 같은 사상이다.
> 컨펌 파일이 **주기적으로 갱신될 성격이면 강력 권장**, 1회성이면 5.1~5.3만으로 충분하다.

값이 확정되기 전이라 **골격만** 정의한다. 컨펌 파일 반영 시 이 표를 채워 회귀 테스트로 쓴다.

|---|--------|------|------|------|
| T1 | CIV 기본 | 체중 ○kg · 약물 ○ · ○mcg/kg/min | ○ ml/hr | ⬜ |
| T2 | CIV 역산 | 체중 ○kg · ○ ml/hr | ○ mcg/kg/min | ⬜ |
| T3 | 볼루스 1회 캡 | 체중 60kg · 20mL/kg | 캡 적용값 + 「상한 적용됨」 표시 | ⬜ |
| T4 | 누적 상한 도달 | 20mL/kg × 3회 | 적색 배너 · 남은 여유 0 | ⬜ |
| T5 | 유지수액 캡 | 체중 80kg | 캡 적용값 병기 | ⬜ |
| T6 | 총 수액 부하 | 유지 + CIV 2종 | 합산 ml/hr 일치 | ⬜ |
| T7 | **미확정 방어** | `FLUID_MAX` 전부 null | **숫자 대신 「— 확인 필요」**, 0·NaN 미표시 | ✅ 지금 정의 가능 |
| T8 | 체중 변경 시 | 누적 300ml 상태에서 체중 변경 | 트래커 자동 초기화 + 안내 | ✅ 지금 정의 가능 |

> **T7이 가장 중요한 테스트다.** 값이 비어 있을 때 앱이 **0을 표시하면 임상 사고**가 된다.
