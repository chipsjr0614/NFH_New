## 1. 요구사항 ① — Norepinephrine 20mcg/ml 표준화

### 1.1 믹스 검산 (요청하신 계산이 맞습니다)

```
Norepinephrine 4mg/4ml 1 amp  =  4,000 mcg
+ D5W 196ml
──────────────────────────────
총 200ml 에 4,000mcg  →  4,000 ÷ 200 = 20 mcg/ml   ✅
```

### 1.2 이 농도를 쓰면 생기는 안전 이점

농도 20mcg/ml에서 주입속도 공식이 **정확히 3배**로 떨어진다.

```
ml/hr = (mcg/min × 60) ÷ 20 = mcg/min × 3
```

→ 간호사가 **암산으로 검산 가능**. 펌프 오설정을 잡아내는 실무적 안전장치가 된다.
(비교: V3의 16mcg/ml는 ×3.75, 40mcg/ml는 ×1.5로 암산 검산이 어렵다.)

### 1.3 표준 속도표 (1~10 mcg/min) — V4 탑재 대상

|---:|---:|---:|---:|---:|
| 1 | **3.0** | 0.017 mcg/kg/min | 0.014 mcg/kg/min | 0.013 mcg/kg/min |
| 2 | **6.0** | 0.033 | 0.029 | 0.025 |
| 3 | **9.0** | 0.050 | 0.043 | 0.038 |
| 4 | **12.0** | 0.067 | 0.057 | 0.050 |
| 5 | **15.0** | 0.083 | 0.071 | 0.063 |
| 6 | **18.0** | 0.100 | 0.086 | 0.075 |
| 7 | **21.0** | 0.117 | 0.100 | 0.088 |

- 체중 기반(mcg/kg/min) 열은 **참고 표시**이며, 표준 조작 단위는 **mcg/min**으로 고정한다.

### 1.4 결정 사항 (2026-08-08 · 칩스 확정)

| # | 쟁점 | 결정 | 상태 |
|---|------|------|------|
| A | **196ml 조제 실무** | **D5W 200ml 백에서 4ml 제거 → NE 4mg/4ml 1@ 주입 (총 200ml)** | ✅ 확정 (1.5 ①안) |
| B | **고용량 구간 볼륨 부담** | **20mcg/ml 단일로 완전 통일.** 고농축 백 병행 없음. 앱은 20mcg/ml 하나만 표시 | ✅ 확정 |
| C | **말초/중심 구분** | **폐지.** V3의 말초 16 / 중심 40 2열 구조를 없애고 단일 농도로 운영 | ✅ 확정 |
| D | **원문 근거와의 차이** | 20mcg/ml는 `순환기계약물투여방법.docx` 원문에 없는 **원내 신규 표준** → 약제부 검증 및 근거 문서화 필요 | ★ 약제부 검증 대기 |
| E | **Only D5W** | V3 주의문구 "★ Only D5W" 그대로 승계 (NS 혼합 금지 표시 유지) | ✅ 승계 |

> **B·C 결정에 따르는 임상 유의점(앱에 경고로 노출할 것):** 20mcg/ml 단일 운영에서 20mcg/min은 60 ml/hr, 30mcg/min은 90 ml/hr가 된다. 승압 요구량이 큰 쇼크 환자에서는 수액 부하가 커지므로, **10 mcg/min을 넘어가는 구간에서는 `⚠️ 고용량 — 수액 부하 확인 · 의국 상의` 경고 배너**를 표시한다.

### 1.5 확정 조제법

```
① D5W 200ml 백에서 4ml 제거
② Norepinephrine 4mg/4ml 1 amp 를 주입
③ 총 200ml · 20 mcg/ml
   ★ Only D5W  ·  ml/hr = mcg/min × 3
```

- 앱 카드 mix 문구(확정): **`D5W 200ml에서 4ml 제거 + NE 4mg/4ml 1@ = 총 200ml (20mcg/ml)`**
- 약제부 최종 검증 전까지 카드에 `★ 약제부 검증 중` 배지를 상시 노출한다.

## 2. 요구사항 ② — 커스텀 믹스 계산기 (신규 탭 「🧮 직접계산」)

"직접 입력해서 계산 가능한가" → **가능하다.** 아래가 그 명세다.

### 2.1 개념

약물별 고정표(V3)와 별개로, **어떤 약이든 실제로 만든 믹스 그대로 입력**해서 속도를 얻는 범용 계산기.

```
[입력] 약물 총량 + 총 볼륨 + (체중) + 목표 용량&단위
                    ↓
[농도 자동 산출] conc = 총량(mcg 환산) ÷ 총 볼륨(ml)
                    ↓
[출력] 주입속도 ml/hr   ←→   역산도 지원 (ml/hr 입력 → 실제 투여 용량)
```

### 2.2 입력 필드 명세

| 필드 | 형식 | 선택지 / 범위 | 기본값 |
|------|------|---------------|--------|
| 약물명 (선택) | 텍스트 or 기존 DB에서 불러오기 | `DRUG_DB` / `HELPER_DRUGS` / `ADULT_DRUGS` 검색 후 프리필 | 비움 |
| **약물 총량** | 숫자 + 단위 | `mcg` / `mg` / `g` / `unit` / `mEq` | mg |
| **총 볼륨** | 숫자 (ml) | 1 ~ 1000 | 100 |
| 앰플 보조입력 | 숫자 × 앰플규격 | 예 `2 @ × 4mg` → 총량 8mg 자동 계산 | 꺼짐 |
| **체중** | 숫자 (kg) | 1 ~ 250 (앱 전역 체중과 동기화) | 70 |
| **목표 용량** | 숫자 | 0 초과 | — |
| **용량 단위** | 드롭다운 | 아래 2.3 표 | mcg/min |
| 목표 ml/hr (역산 모드) | 숫자 | 0 ~ 999 | — |

### 2.3 지원 단위 및 계산식

`conc` = 농도 = 총량(입력단위 → **mcg** 또는 **unit**/**mEq** 환산) ÷ 총 볼륨(ml)
`W` = 체중(kg)

| 단위 | ml/hr 계산식 | 역산 (ml/hr → 용량) |
|------|--------------|---------------------|
| **mcg/min** | `dose × 60 ÷ conc` | `ml/hr × conc ÷ 60` |
| **mcg/kg/min** | `dose × W × 60 ÷ conc` | `ml/hr × conc ÷ 60 ÷ W` |
| **mcg/hr** | `dose ÷ conc` | `ml/hr × conc` |
| **mcg/kg/hr** | `dose × W ÷ conc` | `ml/hr × conc ÷ W` |
| **mg/min** | `dose × 1000 × 60 ÷ conc` | `ml/hr × conc ÷ 60 ÷ 1000` |
| **mg/hr** | `dose × 1000 ÷ conc` | `ml/hr × conc ÷ 1000` |
| **mg/kg/hr** | `dose × W × 1000 ÷ conc` | `ml/hr × conc ÷ 1000 ÷ W` |
| **unit/min** | `dose × 60 ÷ conc` (conc = unit/ml) | `ml/hr × conc ÷ 60` |
| **unit/hr** | `dose ÷ conc` (conc = unit/ml) | `ml/hr × conc` |
| **mEq/hr** | `dose ÷ conc` (conc = mEq/ml) | `ml/hr × conc` |

> 단위 환산 상수: `1 mg = 1,000 mcg`, `1 g = 1,000,000 mcg`. `unit`·`mEq`는 mcg로 환산하지 않고 자체 단위 농도로 계산한다.

### 2.4 출력 명세

1. **농도 배너** — `20.0 mcg/ml` 를 크게. 옆에 산출근거 `4,000 mcg ÷ 200 ml`.
2. **주입속도 대형 표시** — `12.0 ml/hr` (최대 크기, 화면 최상위 정보).
3. **전 단위 동시 환산 카드** — 입력한 목표 용량 하나를 넣으면 mcg/min · mcg/kg/min · mcg/kg/hr · mg/hr 를 **동시에 병기**한다(단위 혼동 사고 방지).
4. **자동 속도표 생성** — 입력한 믹스 기준으로 시작~최대 범위·스텝을 지정하면 표를 즉석 생성 (예: 1~10 mcg/min, 1 step → Norepi 표가 그대로 재현됨).
5. **1시간당 투여량 / 백 소진 시간** — `ml/hr` 로부터 `총 볼륨 ÷ ml/hr = 소진 예상 시간` 표시.
6. **복사 버튼** — 결과 텍스트를 클립보드로 (인계·기록용).

### 2.5 안전 요구사항 (계산기)

- 총 볼륨 0 이하, 총량 0 이하 → 계산 중단 + 명시적 오류 메시지. **0 또는 NaN 결과를 절대 표시하지 않는다.**
- 결과가 **999 ml/hr 초과** 또는 **0.1 ml/hr 미만**이면 경고 배지(`⚠️ 임상적으로 비정상적인 속도입니다 — 입력값을 확인하세요`).
- 소수 자리: 농도 2자리, ml/hr 1자리 반올림. **반올림 전 원값도 툴팁으로 노출**.
- 계산기 화면 상단 고정 문구: `⚠️ 본 계산기는 보조 도구입니다. 최종 투여 전 처방·라벨과 반드시 대조하십시오.`
- 계산기는 **DB 값을 수정하지 않는다** (읽기 전용 프리필만 허용).

### 2.6 사용 예시 검증 (구현 후 이 값으로 회귀 테스트)

| 케이스 | 입력 | 기대 출력 |
|--------|------|-----------|
| Norepi 표준 | 4mg / 200ml / 4 mcg/min | conc 20 mcg/ml, **12.0 ml/hr** |
| Norepi 최소 | 4mg / 200ml / 1 mcg/min | **3.0 ml/hr** |
| Norepi 최대 | 4mg / 200ml / 10 mcg/min | **30.0 ml/hr** |

## 3. 요구사항 ③ — 가독성 / 디자인 개편

### 3.1 V3의 가독성 문제 진단

### 3.2 디자인 방향 — **A+B 혼합 확정** (2026-08-08 · 칩스)

> 결과 카드는 **A안**(대형 숫자 + ◀▶ 스테퍼), 그 아래 접이식으로 **B안**(전체 속도표).
> **C안은 별도 채택하지 않고 「라이트 테마」로 흡수**한다 — 라이트/다크를 양쪽 다 1급 지원하고 토글 상태를 `localStorage`에 저장.
> 아래 3안 설명은 설계 근거로 보존한다.

#### ★ A안 「Clinical Big-Number」 (채택 — 결과 카드)
> **결과 숫자를 화면의 주인공으로.** 정보 계층을 3단으로 강제한다.

```
┌──────────────────────────────────────────────┐
│  Norepinephrine            [20 mcg/ml] [★검증]│  ← 1단: 약물·농도
│  4mg/4ml 1@ + D5W 196ml = 200ml               │
├──────────────────────────────────────────────┤
│            ◀   4 mcg/min   ▶                  │  ← 2단: 조작(스테퍼)
│                                               │
│              12.0                             │  ← 3단: 결과 (48~56px)
│              ml/hr                            │
│   ≈ 0.057 mcg/kg/min (70kg) · 백 소진 16.7h    │
├──────────────────────────────────────────────┤
│  1↓3.0  2↓6.0  3↓9.0  [4↓12.0]  5↓15.0  …     │  ← 보조: 전체 속도표(접힘)
└──────────────────────────────────────────────┘
```
- 장점: 야간·급박한 상황에서 **1초 판독**. 스테퍼(◀▶)로 티트레이션이 손에 붙는다.
- 단점: 한 화면에 한 약물. 여러 약 비교는 표 뷰로 전환해야 함.
- 적용 대상: 성인계산기 · 지속주입 · 신규 직접계산 탭.

#### B안 「Rate Chart」 (채택 — 접이식 속도표)
> 기존 표 구조를 유지하되 **크게·시원하게**.

- 행 높이 33px → **48px**, 본문 13px → **16px**, ml/hr 열만 **20px Bold**
- 얼룩무늬(zebra) + 현재 선택 용량 행 **고정 하이라이트(좌측 4px 컬러바)**
- 장점: V3 구조 그대로라 개발 리스크 최소, 여러 용량 한눈 비교 우수
- 단점: 여전히 "표를 읽는" 행위가 필요

#### C안 「Light Medical」 (라이트 테마로 흡수)
> 배경을 밝게. 흰 카드 + 고대비 텍스트 + 색은 경고에만.

- 장점: 주간 병동 조명·프린트 친화, 의료기기 UI 관행에 부합
- 단점: 야간 병동에서 눈부심 → 그래서 단독 채택이 아니라 **토글 가능한 라이트 테마**로 제공

### 6.2 검증 로그 (260808 · JavaScriptCore 실행)

- 성인 5종 + 지속주입 24종 + 전 탭 초기화 + 탭 전환 7종 **런타임 오류 0건**

## 6.3 지속주입 카드 보강 — 총 볼륨 · 왜 주입 · 주의 (260808 추가)

### 총 믹스 볼륨 — 유도 방식
새 수치를 입력하지 않는다. **이미 있는 앰플규격·희석액·농도로 계산**하고, **두 경로가 일치할 때만 표시**한다.

```
(A) 총 약물량 ÷ 농도        (B) 앰플부피합 + 희석액부피
       ↓                            ↓
       └────── 차이 1ml 이내면 표시 ──────┘
              불일치하면 null → 아예 표시하지 않음 (추정값 미표시)
```

| 약물 | 믹스 | **총 볼륨** | 약물 | 믹스 | **총 볼륨** |
|---|---|---:|---|---|---:|
| Nicardipine | 5@ + 200ml | 250 ml | Lidocaine 2% | 1vial + 80ml | 100 ml |
| Nitroglycerin | 2@ + 80ml | 100 ml | Nitroprusside | 1vial + 248ml | 250 ml |
| Labetalol | 2@ + 160ml | 200 ml | Isoket | 2@ + 80ml | 100 ml |
| Diltiazem | 1vial + 50ml | 50 ml | Amiodarone | 6@ + 582ml | 600 ml |
| Esmolol | 1vial + 240ml | 250 ml | Isoproterenol | 2@ + 98ml | 100 ml |

→ 계산 10종 전부 교차검증 통과. 볼루스·전해질 13종은 믹스 개념이 없어 미표시.
→ 파생 지표로 **«총 250ml 소진 ≈ 10.0시간»** 을 결과 카드에 병기.

### 왜 주입(효능) · 주의 — 연결 방식
`ENRICH`(작용·부작용·`circ.eff`·`circ.caution`)와 `DRUG_DB.caution`은 **이미 앱에 있었으나 지속주입 탭이 읽지 않고 있었다.** V4에서 연결.

- **명시적 매핑 테이블 `HELPER_REF` 사용** — 자동 이름추론 금지. 표기가 다르기 때문(`Lidocaine 2%`↔`2% Lidocaine`, `Labetalol`↔`Labetalol HCI`, `Adenosine`↔`Adenosin`). 실제로 자동 매칭을 시도했을 때 한글명(`히스판주`)이 정규화 후 빈 문자열이 되어 **5종에 잘못 매칭**되는 사고가 있었다.
- **오염 데이터 필터** — `Isoket`의 `DRUG_DB.caution`에 효능 텍스트(`◾효능: …`)가 잘못 들어가 있어 `cleanCaution()`으로 제외.

| 연결 결과 | 종수 |
|---|---|
| 효능·작용·주의 중 하나 이상 연결 | **21 / 23** |
| **원본에 없어 «★ 작성 필요» 표시** | **2** — `Naloxone` · `3% NaCl` |

> ⚠️ 2종은 `DRUG_DB` 94종·`ENRICH` 어디에도 없다. **지어내지 않고 빈칸 + `★ 효능·주의 내용 없음 — 작성 필요` 배지**로 노출한다. → 칩스 작성 대상.

### ★ Milrinone 제거 (260808 칩스 지시)
`HELPER_DRUGS`에서 **Milrinone 항목 삭제** → 지속주입 **24종 → 23종**, 계산 약물 **11종 → 10종**.
함께 정리한 것: `HELPER_KR.milr`(한글 검색어 '밀리논') · `HELPER_REF.milr` · 검색창 placeholder 예시.
**V3(`투약앱_V3.html`)에는 그대로 남아 있다** — V4에서만 제외.

### 표시 위치
- **사이드바(목록)**: `💧 250ml · 혈압강하제` + `⚠️ 12시간마다 IV site 교환`(★줄 우선, 20자 말줄임) + 우상단 ⚠️ 아이콘
- **상세 카드**: 헤더에 `총 250 ml` 칩, 하단에 `왜 주입 / 작용 / ⚠️ 주의 / 부작용` 4행 블록 (프로토콜·참고 카드에도 동일 적용)

### 이때 잡은 버그
`routeUnitKey()`가 **`g`(그램)를 처리하지 못해** `mcg`로 떨어뜨렸다 → Esmolol(2.5g 규격)만 총 볼륨이 안 나옴. `g`/`mcg`/`µg`/대소문자 처리 추가. 수정 후 85개 조합 회귀 재통과 확인.
