# 간호기록 레이아웃 A/B 테스트 (260620)

> **묻는 것 하나:** 사정→진단→중재→낙상(화이트보드 4·5·6·7단계)을
> **단계형(화면 전환)으로 보여줄 때 vs 한 화면(스크롤)으로 보여줄 때**, 어느 쪽이
> 간호사에게 더 잘 읽히고 **덜 빠뜨리게** 하는가.

문서로는 결론이 안 나서(요구사항정의서 ↔ UIUX가이드가 서로 반대) **두 버전을 실제로 만들어 비교**한다.

## ✅ 결정 (2026-06-20)

> **단계형(A)로 간다.** 단, 단계형의 약점("안 보이면 건너뜀")을 막기 위해 두 장치를 더했다:
> 1. **누락 방지 게이트** — 미응답 A&E는 빨간 점선 표시, **맨 아래까지 스크롤 + "확인했습니다" 체크**해야 다음 단계로. (의식/낙상은 의식 선택까지 필수)
> 2. **접이식 라이브 미리보기** — 평소 한 줄(📋 N줄), 탭하면 펼쳐져 전체 기록. 화면 거의 안 먹으면서 실시간 피드백 유지.
>
> → **정본 = `A_단계형_260620.html`.** `B_한화면_260620.html`은 비교 참고용(deprecated).
>
> **데이터:** 지금은 추출본(`nursing_data.json`, 응급실 주호소 ~69개 A&E)으로 **레이아웃 먼저 확정**.
> 마스터(`Nr.statement_*.xlsx`)는 22,184개 진술문 **단어장일 뿐, "주호소별 사정 묶음" 매핑이 없음** →
> 데이터 확장은 *기술 추출*이 아니라 **칩스의 임상 큐레이션 작업**으로 분리(지어내지 않음).

## 두 버전 (변수는 '레이아웃' 하나뿐)

데이터·색·컴포넌트·진술문은 **완전히 동일**(공유 코어). 오직 배치만 다르다.

| | **A 단계형** (`A_단계형_260620.html`) | **B 한화면** (`B_한화면_260620.html`) |
|---|---|---|
| 철학 | TurboTax/Typeform — 한 번에 한 덩어리 | v4 — 한 화면 + 실시간 미리보기 |
| 진행 | 주증상 → (분기) → 주호소별 사정 화면 → 의식/낙상 → 기록 팝업 | 위에서 아래로 한 스크롤에 전부 |
| 기록 확인 | **끝에 팝업**으로 검토 | **하단 시트로 실시간** 누적 |
| 진행 표시 | 상단 진행바(4단계) | 없음(스크롤 위치) |
| 누락 가시성 | 다음 화면이 안 보임(가이드의 우려) | 안 한 항목이 한눈에(화이트보드의 의도) |

공통: 주증상 15개·분기 트리, 있음(빨강)/없음(회색) 토글, 통증 NRS(비고),
📢환자설명↔P&E 양방향, 진단 자동, 의식/낙상(낙상위험 자동), EMR 복사.

```
nfh_core_260620.js    ← 데이터(=_archive/nursing_data.json 추출, 15 대분류)+로직 ★정본
nfh_ui_260620.js      ← 공유 렌더 엔진(사정·NRS·환자설명·낙상·미리보기)

```

- **오프라인 단일 HTML 원칙과의 차이:** 테스트 편의상 코어/UI/CSS를 분리(`<script src>`)했다.
  병원 배포본(`app/index.html`)으로 확정되면 **승자 1개를 인라인 단일 HTML로 합본**한다.
- 로컬 실행: 폴더에서 `python3 -m http.server` 후 브라우저로 두 파일 열기(또는 그냥 더블클릭).

## 테스트할 때 볼 것 (관찰 포인트)

신규 1명·베테랑 1명에게 **같은 가상 환자**(예: 복통+호흡곤란, 두통 같은 항목 많은 증상)를 둘 다로 입력시키고 본다.

1. **누락** — 어느 쪽이 항목을 덜 빠뜨리나? (특히 ⚠️혈변·임신가능성 같은 "한 번은 물어야" 항목)
2. **속도** — 한 환자 입력 완료까지 시간. 베테랑은 빠른 모드("다 정상으로")를 쓰나?
3. **가독성** — 항목 많은 증상(호흡 11개)에서 한 화면(B)이 빽빽해 안 읽히나? 단계형(A)이 답답하나?
4. **안심감** — 지금 뭘 기록 중인지 아는 느낌은? (B의 실시간 미리보기 vs A의 끝 검토)
5. **중단 복귀** — 옆 환자로 끊겼다 돌아올 때 어디까지 했는지 찾기 쉬운 쪽은?

## 데이터 무결성

- A&E·D·P&E 진술문은 **마스터 추출본(nursing_data.json) 원문 그대로**. 임의 생성·수정 없음.
- NRS(강도·부위·양상·기간·지속)는 정형 진술문이 아니라 **비고란 전용**.
- 있음/없음 **색 강조는 UI 표시일 뿐** 진술문을 바꾸지 않는다(휴리스틱 `posOf`).
- `감염`·`고체온` 등 일부 블록 D에 P&E로 보이는 라벨 혼입은 **원본 그대로 표시**(마스터 정정 시 데이터만 교체).
