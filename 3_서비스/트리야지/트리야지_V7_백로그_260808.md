### [x] ① 발열 — 내원 전 해열제 (약물·용량·복용시각)

**적용 범위(칩스 확정 260808):** `발열`·`소아 발열` **주호소 모듈에만**. 발열을 주호소로 고르지 않은 환자(인후통·복통 등)에는 안 뜬다.

`ANTIPY(ped)` 생성기로 두 모듈에 같은 문항 6개를 넣었다. `내원 전 해열제 복용`이 **있음일 때만** 나머지가 열린다(`showIf`) — 평소 화면 길이는 그대로.

| 문항 | 입력 | 비고 |
|------|------|------|
| 💊 내원 전 해열제 복용 | 있음/없음 | 이걸 골라야 아래가 열림 |
| 해열제 종류 | 아세트아미노펜 / 이부프로펜 / 덱시부프로펜 / 기타 / 모름 | 소아는 챔프·맥시부펜 등 소아 제품명 예시 |
| 약 이름 (직접 기재) | 자유 입력 | 종류=`기타`일 때만 |
| 1회 복용량 | 자유 입력 | 성인 `500mg / 1정`, 소아 `시럽 5mL / 좌약 125mg` |
| 마지막 복용 | 30분 이내 / 1시간 / 2~3시간 / 4~6시간 / 6시간 이상 / 모름 | 재투약 간격 판단용 |
| 복용 시각 (아는 경우) | `06:30` | 적으면 위 "몇 시간 전"은 **기록 문장에서 자동 생략** |

**소아 용량은 입력·기록만** (칩스 확정 260808) — mg/kg 환산 표시·과용량 판정은 **넣지 않았다**. 임상 기준치가 필요한 판단이라 칩스 확정 전에는 만들지 않는다.

**출력 예시**
```
상기 39세 남환, 1일 전(금)부터 발열로 내원함 (오한 있음, 내원 전 해열제 복용 있음,
아세트아미노펜 (타이레놀 등), 용량 500mg, 마지막 복용 06:30).
```

### [x] ② 출혈량 정량화 — 눈대중 환산 (토혈·코피·객혈·일반 출혈)

**방식(칩스 확정 260808):** 전용 위젯이 아니라 **선택지 라벨에 생활 단위 환산을 넣는 방식**. 화면 조작이 늘지 않고 기록에 그대로 찍힌다.

```
묻어나는 정도 (거즈·휴지 적심)
숟가락 1~2술 (약 15~30mL)
소주잔 1잔 (약 50mL)
종이컵 반 컵 (약 100mL)
종이컵 1컵 (약 200mL)
종이컵 1컵 이상 (200mL 초과)   ← 빨강 강조
모름
```

`BLEED_Q(부위명, id접두, 조건)` 생성기가 **4문항 세트**(양 환산 / 양 직접 기재 / 횟수 / 현재 지혈 상태)를 만든다. 적용 위치:

| 주호소 | 적용 | 조건 |
|--------|------|------|
| 출혈 | 기존 `소량·중등도·대량` → 환산 칩으로 **교체** | 항상 |
| 코피 | 세트 신설 + `출혈 지속시간`(5분 이내/5~20분/20분 이상) | 항상 |
| 구토/오심 | 토혈량 세트 신설 | **토혈=있음일 때만** 열림 |
| 객혈 | 객혈량 세트 (아래 ③ 신설 모듈) | 항상 |

- **양 직접 기재**를 쓰면 환산 칩은 기록 문장에서 빠진다(`mutedBy`) — 화면과 참고줄에는 둘 다 남는다.
- 현재 지혈 상태 `출혈 지속 중`은 빨강 강조.
- **KTAS 판정에는 반영하지 않았다**(칩스 확정 260808). `calcKTAS()` 무변경 — 기록·인계 전달용 정량화까지만.

### [x] ③ `객혈` 주호소 모듈 신설

169 목록에는 있었지만 세부질문 모듈이 없어 **서술 문진으로 빠지던** 주호소였다. 객혈량 정량화를 붙이려면 모듈이 필요해 신설.

- 문항: 객혈량 4종 + 양상(가래 혈흔/선홍색/검붉은/거품) + 기간 + 기침 + 호흡곤란 동반 + **결핵 과거력·접촉력** + 항응고제.
- 기침 문항(`cough`)이 있어 **선택 시 1구역(감염 격리)·마스크 안내가 자동으로 뜬다**(기존 `respFlag()` 로직). 객혈 환자에서 결핵 배제 전 마스크 안내는 의도한 동작.
- 🔶 **track(severe)·Red Flag 5개는 출혈 모듈을 준용한 초안 — 칩스 확정 필요.**

### [x] ④ FIND 학대 선별 — 대상 환자 **필수 입력** (260808 칩스 요청 · 문항 원문 제공)

**도구 원문은 칩스가 교육받아 전달한 것 그대로 넣었다. AI가 문항을 만들거나 바꾸지 않았다.**

**구성 = 관찰 7 + 확인질문 3**

| 👀 ① 관찰 7가지 — 묻지 말고 보면서 확인 | 안내문 |
|---|---|
| 1. 멍·상처·화상 | 피부에 멍·열상·화상이 있는지 |
| 2. 여러 부위 손상 | 한 곳이 아니라 여러 부위에 손상 |
| 3. 비정상적인 부위의 멍 | 등·엉덩이·귀·목·안쪽 허벅지 등 |
| 4. 특이한 손상 형태 | 손가락 모양·물체 모양·벨트 모양 등 |
| 5. 손상 단계가 서로 다름 | 오래된 멍과 새 멍이 섞여 있음 |
| 6. **아동의 행동** | 과도한 공포·위축·보호자 회피 등 |
| 7. 보호자의 행동 | 과도한 분노·위협·책임 전가·지나친 무관심 등 |

| 🗣️ ② 확인질문 3가지 | 확인 목적 |
|---|---|
| 1. 어떻게 다쳤나요? | 사고 경위와 손상 양상 비교 |
| 2. 언제, 어디서 다쳤나요? | 시간·장소 및 **치료 지연 여부** |
| 3. 그때 누가 함께 있었나요? | 당시 상황과 동행자 |

**대상·필수화**
- **만 12세 이하 · 만 70세 이상 → 카드 자동 표시 + 필수.** 10문항을 모두 응답해야 `기록 생성 → 최종확인`이 열린다(미응답 항목을 alert에 나열 + 카드로 스크롤).
- 13~69세는 `🔍 FIND 학대 선별 열기` 버튼으로 **수동 시행**(강제 아님). 하다 만 것은 기록에 남기지 않는다.
- 기존 앱의 소아(<15)·노인(≥65) 기준과 **다른 별도 판정**(`findChild`/`findElder`) — 소아 모드·소아 V/S 등 기존 동작에는 영향 없음.
- 관찰 6번은 **성인 대상이면 라벨이 `환자의 행동`으로 바뀐다**(70세 환자에게 "아동의 행동"은 안 맞으므로).

**"제대로 물어보고 평가받는" 구조로 만든 부분**
- **체크박스가 아니라 `[없음][있음]` 이지선다.** V6의 학대 카드는 체크박스형이라 아무것도 체크 안 된 상태가 *"물어봤는데 아니었다"* 인지 *"아예 안 물어봤다"* 인지 구분이 안 됐다. 평가에서 가장 지적받기 쉬운 지점.
- **음성(해당 없음)도 기록에 남긴다** — `FIND 학대 선별(12세 이하) : 관찰 7항목 해당 없음 · 어떻게 다쳤나요? … · 언제, 어디서 … · 누가 함께 …`. 시행했다는 증거가 남는다.
- **일괄 '전부 아니오' 버튼은 두지 않았다** — 형식적 통과 방지. 다만 확인질문 3개에는 `해당없음` 버튼을 뒀다(외상이 아닌 내과 환자에게는 실제로 해당 없음. 기록에는 `해당 없음(외상 아님)`으로 남아 증거가 된다).
- **상태 표시줄** — `미응답 3개` / `해당 2개 · 아래 학대 의심 사정을 함께 시행하세요` / `✅ 10문항 시행 완료 · 해당 없음`.
- **S1 배지 연동** — 대상 환자면 첫 화면에 `만 12세 이하 — FIND 학대 선별 대상 · 지금부터 관찰 7항목을 보세요`. 관찰은 말 걸기 전부터 해야 하므로.

**기록 위치(비고)** — 특이사항 칸. 엑셀·네이버웍스·Reminder2·간호기록 **4종 모두에 자동 반영**된다. 양성이면 `$`·🔴가 붙고 S5 주의 박스에도 뜬다.
> ⚠️ 병원 초진기록지에 '비고'라는 별도 칸이 따로 있다면 알려주세요 — 지금은 앱의 특이사항 칸으로 나갑니다.

**기존 학대 의심 스크리닝 카드와의 관계**
- 카드는 **그대로 두되**, 자동 열림 조건을 바꿨다. V6는 소아·노인·외상이면 무조건 열려 화면이 길었는데, **이제 FIND에서 '있음'이 하나라도 나오면** 열린다. 1차 선별은 FIND, 상세 근거 수집은 기존 카드가 맡는 2단 구조.

**🔶 칩스 확정 필요**
- **양성 판정 기준** — 몇 개 이상이면 '학대 의심'인지. 앱은 지금 **'있음' 개수와 항목명을 세어 표기만** 하고 자동 판정·KTAS 승격은 하지 않는다.
- **양성 시 조치 절차** — 신고 라인·사회사업팀 연락 등 원내 절차. 지금은 기존 신고 의무자 안내문만 표시.
- **시행자·시행시각 기록 여부** — 평가에서 요구되면 추가 필요.
- **보호자 분리 문진 요건** — FIND 지침에 있으면 화면 안내 배너 추가 가능.

### [x] ⑤ 엔진 보강 (위 건들을 위해 필요했던 최소 변경)

- **`inNote`** — `buildPresentDraft()`는 자유 입력(text) 문항을 **전부 문장에서 제외**하고 있었다(해열제 용량·양 직접 기재가 기록에 안 남는 원인). `inNote:true`를 단 문항만 문장에 포함하도록 1줄 변경. **기존 문항은 동작 무변경**(소아 발열 체온 `bt_v`, 산과 임신주수 `ga` 등은 지금도 문장 제외 그대로).
- **`mutedBy`** — 더 구체적인 답이 있으면 덜 구체적인 문항을 문장에서 생략(양 직접기재↔환산 칩, 정확 시각↔몇 시간 전).
- **`cols:1`** — V6까지 데이터에 선언만 되고 **쓰이지 않던 속성**. 실제로 세로 1열 렌더가 되게 했다. 라벨이 긴 출혈량 칩 때문에 필요. ⚠️ 부수 효과로 기존 `출혈-부위`·`정신과-주요 문제`도 세로 배치가 된다(원 설계 의도대로 복원, 가독성 개선).

## 2. 검증 결과 (260808)

JavaScriptCore로 데이터·문장 엔진을 직접 돌려 확인:

- 문장 조립 7개 시나리오(성인 발열·소아 발열·코피 칩/직접기재·토혈·객혈) 정상
- `showIf` 동작 — 발열 모듈 문항 수 6개 ↔ 10개(해열제 있음)
- `esc2` 빨강 강조·`cols:1` 세로 렌더 정상
- 칩 라벨에 원시 부등호(`<`, `>`) 없음 → HTML 파싱 안전
- **CC 27개 모듈 무결성 검사 통과**(중복 id·esc2 불일치·showIf/mutedBy 대상 누락 0건)
- 간호기록·엑셀 13칸 TSV 전체 출력 확인 — 이름 마스킹·`•` 불릿·🔴 유지
- `calcKTAS()` 결과 무변경 확인

**FIND**
- 대상 판정 경계값 — 12세 ⭕ / 13세 ❌ / 18개월 ⭕(개월 표기) / 69세 ❌ / 70세 ⭕ / 85세 ⭕
- 미응답 카운트 — 전부 미응답 10개 → 관찰만 완료 3개 → 전부 완료 0개
- **최종확인 차단 동작 확인**(8세·미응답 → alert + 진행 중단)
- 음성 요약·양성 요약(`$`+🔴) 문자열, 간호기록 `[특이사항]`·엑셀 12번 칸 반영 확인
- 관찰 6번 라벨 전환(8세 `아동의 행동` ↔ 72세 `환자의 행동`)
- 상세 학대 카드 자동 열림 — FIND 양성 ⭕ / 음성 ❌
- 비대상(40세)이 하다 만 경우 기록에 안 나감
- 자동저장 스냅샷에 `S.find` 포함 확인

> ⚠️ **브라우저 실기 테스트는 아직** — 화면 렌더·클릭·자동저장은 실제 쓰는 브라우저에서 1회 확인 필요.
